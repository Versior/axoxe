# 音乐接口故障换源

Meting API 留空时，播放器使用内置公共接口。候选清单在 `web/public/music-apis.json`，当前来源为服务作者公开的 [Injahow Meting API](https://github.com/injahow/meting-api#demo) 和 [圆弧派 Meting API](https://v.iarc.top/)。

正常播放不刷新清单。只有元数据请求失败、返回无可播放歌曲，或音频元素报告播放源错误时，播放器才读取二开仓库最新的候选清单，并逐个尝试这首歌。清单无法下载时继续使用内置候选。

每个元数据请求最多等待 8 秒。失败接口在当前音乐卡片中被排除，避免循环；成功的接口按音乐平台和自定义配置在本次页面会话中记住。修改候选清单后，已部署的播放器在下一次故障时即可读取，无需为清单变化重新构建镜像。

填写自定义 Meting API 时优先使用该地址，故障后同样尝试公共接口；不会改写系统设置中的地址。普通地址及 `:server`、`:type`、`:id`、`:auth`、`:r` 参数模板均受支持。

播放器使用实际音频的时长。如果来源只提供 30 秒试听，播放条也只显示 30 秒。公共接口不保证每首歌都能播放完整版，曲目授权、账号权限、地区和接口状态都会影响结果。需要完整播放时，优先使用有权提供完整音频的自建或可信 Meting 接口；Apple Music 则由官方嵌入播放器决定可播放的内容。

新增服务前需确认服务作者明确提供公开接口，并验证歌曲数据、CORS 和 HTTPS 音频。该功能没有定时任务。
